  MiniMax M3 paged sparse attention（MSA）长 prefill 做进一步延迟定位，产出一个
  可回滚的源码候选 + 配对验证。
- 专用克隆：`/workspace/agent-workspaces/msa-stage-profile/.cache/agent-workspaces/msa-long-prefill-overnight-984069d`
  分支 `agent/enflame-msa-long-prefill-overnight`，基线 `984069d7e0e57791f3ffcbe2639fff1f10905423`。
- 设备：仅 GCU 5（PCI `0000:83:00.0`），CPU `160-191`，`set_device(5)`。全程未触碰其他卡。
- 运行环境：`/flagos/bin/python`（Python 3.12.13）、torch 2.10.0+cpu、Triton 3.6.0（GCU 后端），
  `PYTHONPATH="$PWD/src:$PWD:/opt/flagtree"`，`TRITON_CACHE_DIR=/tmp/msa009-triton`。

## 0. 结论摘要

**保留一个候选，但默认路由不变（opt-in）。**

在 BF16 固定形状（B/Q/KV/Hkv/Hq = 1/1024/16384/1/8，D=128，page=128，TopK=16）上，
把 direct kernel 每页的 V DMA 从「QK → 在线 softmax → 输出缩放」之后提前到 QK 之前
发射（纯调度重排，数学、页序、累加序完全不变），得到：

| 指标 | 基线（默认路由） | 候选（opt-in） | 加速 |
|---|---|---|---|
| `minimax_m3_sparse_attn` 单算子 | 5.3937 ms | 4.8034 ms | **1.1229×** |
| 完整链路（index_score→index_topk→sparse_attn） | 6.7828 ms | 6.1830 ms | **1.0970×** |

三次独立运行（9/9/11 轮交替 A/B）复现：单算子 1.1209× / 1.1222× / 1.1229×，
全链路 1.0975× / 1.0941× / 1.0970×。候选与基线输出**逐位相同**（maxdiff 0，
1048576 元素中 0 个不同），与独立 FP32 参考的偏差与基线完全一致。

机制证据支持这个方向：direct kernel 在 1024 个 program 上近似线性扩展
（约 4.7 µs/program），每 program 64 KiB 共享内存、卡上仅 2 个 SM，因此
**页内串行链**而非占用率是瓶颈；V 的 DTE 等待原本夹在两次 convgen 之间，
提前发射后与 QK convgen 及 softmax 重叠。

同时**排除**了三条同方向与另一方向的候选（见 §4、§5），并纠正了本轮中我自己
两个探针的错误（见 §7），其中一条曾被误读为「基线存在越界读掩码泄漏」。

完全复用上游 benchmark 的构造，不新增形状、不改 `tests/` 与 `benchmark/`：

  = `(1, 1024, 16384, 1, 8)`，即 batch 1、query 1024、KV 16384、kv head 1、q head 8、D 128。
- 数据：`make_data(...)`，`generator.manual_seed(args.seed + shape_index)` → 本形状 seed 6；
  物理页用 `torch.randperm` 后 `kv_cache[physical_pages.argsort()]`，与上游一致。
- score→topk：上游真实 `minimax_m3_index_score` + `minimax_m3_index_topk`（TopK 16，init 1，local 2）。
- 精度 bf16，mask 与上游一致。
- 共享前缀：`USE_SHARED_PREFIX=True` 生效，64 个 16-query 组的 `counts` 全为 3，
  因此 direct kernel 实际跑 13 页（不是 16 页）。这是既有行为，本任务未改动。

## 2. 候选实现（`src/flag_attn/runtime/backend/_enflame/msa/sparse_attn.py`）

改动共 43 行增 / 14 行删，全部落在 direct kernel 与其 host 入口：

1. `_gqa_sparse_fwd_direct` 签名末尾新增 `EARLY_V_DMA: tl.constexpr = False`。
   默认 `False`，因此**任何既有调用点的编解码结果与默认路由逐位不变**。
2. 把 V 的 `tl.make_block_ptr` 构造上移到 `qk_dot = tl.dot(q_qk, tl.trans(k))` 之前；
   在 `EARLY_V_DMA and not USE_FP8` 时先发 `tl.load(v_ptrs, ...)`，否则仍在原位发。
   V 指针只依赖 `k_base_ptr` / `head_dim` / `stride_kv_d`，上移不改变语义。
3. host 侧新增 opt-in：仅当 `head_dim == 128 and block_size_h <= 8` 且环境变量
   `FLAG_ATTN_MSA_EARLY_V_DMA=1` 时置位。默认（不设该变量）走原路径。

**默认路由未改变**，这不是新的自动路由：开关关掉即完全回到 `984069d` 的行为。
FP8 路径（`USE_FP8`）显式走原顺序，未受影响；grouped8 / decode kernel 未改动。

- 独立 FP32 参考为 `agent-results/msa009_overnight.py::torch_reference`：逐页 torch float32

- 「默认路由逐位一致」用 `984069d` 未改动工作树上记录的输出 sha256 比对

- 形状 1 的 bypass 回归是任务要求的既有 `B1/Q512/KV4096` 路径；实测该形状
  **走 `_gqa_sparse_fwd_grouped8`**（`block_table` 宽 32 ≤ 2×topk=32），而 main 形状走
  `common_prefix + fwd_direct`（宽 128 > 32）。即候选所在 kernel 不服务该形状，
  但仍确认 grouped8 结果未被波及（逐位一致、掩码成立）。

### 3.1 掩码的可证伪检查（对两条路由都做）

不是「检查有没有 NaN」，而是按行做**逻辑位置**污染：

- 对采样行 r，把 `blk*128+o > q_abs(r)` 的位置（r 必须看不到）写成一个有限大值，
  要求 r 的输出**逐位不变**；
- 反向对照：把 r 可见的窗口写成大值，要求 r 的输出**必须改变**（证明污染确实进入 kernel）。

结果（`raw/round3/mask2_candidate.json`、`mask2_pristine.json`）：
main 形状 8 行、bypass 形状 8 行，**全部 ENFORCED**（future changed=0，control changed=1024），
基线 `984069d` 与候选完全一致。污染值 5 / 100 / 30000 都试过，位移随污染值成线性，
说明这确实是掩码在起作用，而不是数值溢出。

## 4. 轮次记录

每轮先写假设与判据，只改一个变量，候选独立可回滚，再同卡同样本交替 A/B。

### 轮 1：V DMA 提前（保留）

- 假设：每页 V 的 DTE 等待夹在 QK convgen 与 PV convgen 之间，属于串行暴露；
  提前发射可与 QK/softmax 重叠，且不改变任何数值。
- 判据：逐位相同 + 单算子中位数改善 ≥ 5% + 全链路同向改善。
- 结果：逐位相同；单算子 5.3755→4.7957（1.1209×），全链路 6.7758→6.1738（1.0975×）。**保留**。
- 同时用探针确认机制（`raw/round1/`）：
  - program 数缩放：32→0.6400、64→0.7347、128→1.0753、192→1.3062、256→1.6473、
    384→2.2309、512→2.9099、768→4.0557、1024→5.3175 ms；约 4.7 µs/program、近线性
    ⇒ 未饱和，per-program 串行链主导。
  - 页内再切分（SUB=2/4）：11.8365 / 14.9217 ms，均退化 ⇒ 64 KiB 整页 tile 已是甜点。
  - DMA 提升消融（非等价诊断）：`k_hoist` 3.4815、`v_hoist` 4.7843、`kv_hoist` 2.3992
    vs base 5.3175 ⇒ K DMA 约占 1.84 ms（35–42%/页），V DMA 约 0.53 ms。
  - 转置 K 载入（免 `tl.trans`）：逐位相同但只有约 1%，不是主因；与 V 提前叠加无额外收益。

### 轮 2：跨页 K 预取 / DMA 全提前（排除）

- 假设：V 已提前后，剩余链是 K DMA → QK → softmax，把下一页 K 在 QK 之后预取应能隐藏 K。
- 判据：逐位相同 + 中位数改善 ≥ 3%。
- 结果（`raw/round2/`）：
  - 同 buffer 跨页携带 K：**SIP 异常，进程被杀**（此路不再重试）。
  - QK 之后重新取下一页 K：5.5756 vs 5.3943 ms，**更慢**。
  - 两个 DMA 都提到页首 + 页号 gather 流水：4.9086 vs 4.7957 ms，**更慢**。
- 解释与结论：页 tile 已占满 64 KiB 单缓冲、卡上仅 2 SM，再持一个 K tile 的代价
  （共享内存/寄存器压力）大于它隐藏的传输。**K 在本形状不可被隐藏**，保留轮 1 不变。
- 本轮还修了 harness 的一个真实缺陷：staged profile 会继承配对 A/B 遗留的开关，
  导致「基线/候选分段」实际同路由。现在两臂各自在显式 env 上下文内测量，
  并断言两路由逐位相同、跑完 env 已复位。

### 轮 3：L2 驻留策略 / 更大 tile（排除，停止）

- 假设：13 页取自 128 条表项、被 1024 个 program 反复重读，给 KV 载入加
  `evict_last` 可提高 L2 命中。
- 判据：逐位相同 + 中位数改善 ≥ 3%。
- 结果（`raw/round3/`）：4.7432 vs 4.7461 ms（约 0.06%，在噪声内），**无收益**。
- 停止条件触发：轮 2、轮 3 连续两轮无可复现改善 ⇒ 按任务约定停止实验，
  不再开新方向，保留轮 1 候选并转入交付。

## 7. 自我更正（保留为证据）

本轮有两个探针一开始给出错误结论，均已定位、修正并保留原始（错误）版本：

1. **掩码探针 v1（错误）**：按「物理页偏移」污染，而 kernel 是按**逻辑位置**
   `blk*128+o`（`blk` 是页表下标，物理页是它的随机置换）做掩码。因为两者错位，
   v1 在 bypass 形状上误报「row 1..256 掩码泄漏、位移随污染值线性」。
   用 pristine `984069d` 工作树对照后确认该误报在基线同样出现（即与候选无关），
   再按逻辑位置重写后，两条路由、两种形状、16 行**全部 ENFORCED**。
   版本留存：`raw/round3/probe_mask_v1_buggy*.py`、`mask_v1_buggy_poison5_pristine.json`。
2. **轮 2 `early_v` 对照（错误）**：该变体没有推进页号，属无效对照（其 maxdiff 非 0 已自证），
   同批的 `dma_first_pipe` 是有效对照（逐位相同）并被采纳为负结果。

这两处都不影响候选数据（候选的 A/B 与逐位比较都走真实 host 入口、且经过
`--verify` 的独立 FP32 参考与 sha256 摘要校验）。

## 9. 已知限制

- 本报告的计时是**算子级（operator-level）**测量：`torch.gcu.Event` 包住单次调用，
  不是调度器独占门禁的正式基准；正式复测由调度器在会话后执行。
- 候选收益来自 V DMA 与 QK/softmax 的重叠，只对 `head_dim==128`、`block_size_h<=8` 的
  BF16 direct 路径生效；FP8、grouped8、decode 未受益（也未受影响）。
- 增益在 1.09–1.12× 量级；三次独立运行一致，但仍属同一卡同一时段，跨机/跨版本需复测。
- 全程未改变真实 KV cache 布局，也不需要上层改数据；无预处理被移出计时。
  候选不改变内存足迹（`shared=65536`、`num_warps=1`、`num_stages=1` 均与基线相同）。
