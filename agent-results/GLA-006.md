## Planned change (experimental, default off)

Add opt-in env flags (default 0), so production dispatch is byte-for-byte unchanged:
- `FLAGGEMS_ENFLAME_GLA_EXPERIMENTAL_FP16_STATE=1`: admit FP16 K/V shapes outside the legacy whitelist to the existing local-state kernels.
- `FLAGGEMS_ENFLAME_GLA_EXPERIMENTAL_FP32_STATE=1`: admit FP32 K/V to the same kernels for small-shape compile/numerical smoke only.

The existing guards (`cu_seqlens is None`, `BS==BT`, `BT==64`, `HQ==H`, `not state_v_first`, `g is None`, `g_gamma is None`, `gk is not None`, `gv is None`, dtype agreement, `PARALLEL_STATE_ENABLED`, `PARALLEL_BWD_STATE_ENABLED`) stay unchanged. No default whitelist is widened.

## Correctness thresholds

Per tensor (`o, ht, dq, dk, dv, dg, dh0, h, ht_state, dh, dh0_state`): both sides finite and (`max_abs <= 1e-6` or `relative RMS < 4e-3`), matching GLA-005/GLA-004. Rows report NaN/Inf, shapes, max_abs and relative RMS. Path counters record actual launches of `_chunk_fwd_local_state_kernel`, `_chunk_fwd_state_scan_kernel`, `_chunk_bwd_local_state_kernel`, `_chunk_bwd_state_scan_fp32_2d_group_kernel`, plus fallback `chunk_fwd_kernel_h` / `chunk_bwd_kernel_dh`. Cold compile is recorded separately and never used as speed evidence.

## Phase 2 (running)

BF16 uses the existing unrestricted parallel route (no flag), so its rows only need a real-launch check plus old-tree comparison. FP32 needs `FLAGGEMS_ENFLAME_GLA_EXPERIMENTAL_FP32_STATE=1` and is smoke-only: B1/T128/H1, K=V=64 plus asymmetric 32x64, 64x32, 32x32, `states_in_fp32=False` on the forward route and the FP32 2D-group backward scan. The extra `STATE_IN_FP32=(states_in_fp32 or k.dtype == torch.float32)` specialization in the diff exists only because a literal FP32->FP32 conversion fails Enflame layout removal in the scan kernel; it is exercised only when the opt-in FP32 flag is on.
