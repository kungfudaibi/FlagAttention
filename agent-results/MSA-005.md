## 2. What was repaired (validation only)

Two validation holes were found and fixed; the candidate source was untouched.

1. `agent-results/scripts/msa003_ab.py` hard-coded `MSA-004/ab.jsonl`, so a run
   from this clone would have overwritten another task's committed evidence.
   It now writes to `MSA_AB_OUT` when set and otherwise to
   `/tmp/msa005_ab.jsonl` — a formal re-run cannot dirty this branch. The same
   script now records `current_device`/`current_stream`, checks the efsmi DEV 2
   PCI address, and **exits non-zero before the sweep** if the device or stream
   binding is wrong.
2. `tests/flag_attn/test_msa_group16.py` now asserts per case that the current
   device, the current stream and the allocated tensors are all on
   `gcu:${S60_TEST_DEVICE}`; previously a silent rebound to device 0 would still
   have passed.

Both are exercised by the runs below. The pre-existing negative controls from
MSA-004 (wrong sample count, reference shift, wrong gate expectation) still
apply and are not re-run here; a new stream-binding negative control was added.
