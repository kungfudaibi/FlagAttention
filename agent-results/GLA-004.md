# GLA-004：FP16 不同 K/V 状态尺寸的并行路径扫描

## 结论（短）

在 `4f437de` 的并行状态内核上，**只把 FP16 的准入谓词从 `K==64 and V==64`
换成显式形状白名单** `{32x32, 64x64, 64x128, 128x64, 128x128}`，四个候选尺寸
全部真实命中并行 `chunk_fwd_h` / `chunk_bwd_dh` 路径，与精确基线提交逐张量对比
`o/ht/dq/dk/dv/dg/dh0` 及状态 `h/ht/dh/dh0_state` 均通过（rel_rms <= 6.4e-6，
max_abs <= 9.8e-4，无 NaN/Inf，两侧退出码 0）。

状态阶段收益非常大且 3/3 轮可复现（B1,T256,H4，FP16，`gate_logit_normalizer=1.0`，
中位数对中位数）：

| 形状 | `chunk_fwd_h` | `chunk_bwd_dh`(FP32) | 整个前向 |
|---|---:|---:|---:|
| 32x32 | 1.252 -> 0.156 ms (8.0x) | 1.225 -> 0.212 ms (5.8x) | 1.414 -> 0.391 ms (3.6x) |
| 64x64（控制） | 0.161 -> 0.163 ms (1.0x) | 0.219 -> 0.211 ms (1.0x) | 0.378 -> 0.386 ms (1.0x) |
| 64x128 | 6.815 -> 0.182 ms (37.5x) | 6.514 -> 0.231 ms (28.2x) | 6.986 -> 0.409 ms (17.1x) |
| 128x64 | 6.800 -> 0.192 ms (35.4x) | 6.559 -> 0.245 ms (26.7x) | 7.040 -> 0.457 ms (15.4x) |
| 128x128 | 12.327 -> 0.183 ms (67.3x) | 11.832 -> 0.230 ms (51.4x) | 12.596 -> 0.473 ms (26.7x) |

64x64 控制组前后完全一致，说明差异来自候选形状的分流，而不是测量漂移。
端到端（fwd+bwd）提升方向一致但**噪声很大**（见"不确定性"）：64x64 控制组
两侧是同一路径，端到端仍出现 18.2 vs 19.6 ms 的差异；因此本报告不把端到端
倍数当成可靠结论，只把状态阶段与整个前向的稳定差异作为证据。

**是否值得扩展生产分流**：32x32 / 64x128 / 128x64 / 128x128 的**状态阶段**
值得进入后续 shape-specific 评审（收益 5.8x–67x，且数值与基线一致）。但这是一次
单机、单 B/H/T 组合为主的实验，端到端噪声未压住，**不建议**直接把实验白名单
合入生产；生产化需要按形状分别给出门槛、补 B/H/T 覆盖与端到端重复测量。

## 改动（仅为实验，分支内）

`src/flag_attn/runtime/backend/_enflame/FLA/chunk_h.py`：

1. 新增常量 `EXPERIMENTAL_FP16_PARALLEL_STATE_SHAPES = frozenset({(32,32),(64,64),(64,128),(128,64),(128,128)})`；
2. `chunk_fwd_h` 的 `use_parallel_state` 中，把
   `k.dtype == torch.float16 and K == 64 and V == 64` 换成
   `k.dtype == torch.float16 and (K, V) in EXPERIMENTAL_FP16_PARALLEL_STATE_SHAPES`；
3. `chunk_bwd_dh` 的同一谓词做同样替换。

其余保护条件（`cu_seqlens is None`、`BS == BT`、`BT == 64`、`HQ == H`、
`not state_v_first`、`g is None`、`g_gamma is None`、`gk is not None`、
`gv is None`、dtype 一致性、`PARALLEL_STATE_ENABLED`）全部保持不变。
BF16 分支不变。回退只需 `git revert` 该提交或删除该常量引用。

## 路径是否真的命中

探针在进程内包裹 `_chunk_fwd_local_state_kernel`、`_chunk_bwd_local_state_kernel`、
`_chunk_fwd_state_scan_kernel`、`_chunk_bwd_state_scan_fp32_2d_group_kernel`、
`chunk_fwd_kernel_h`、`chunk_bwd_kernel_dh` 的 launcher 并按调用计数，结果写入
每条 raw JSON 的 `path_*` 字段。T256 实测：

| 形状 | 基线 fwd_h | 候选 fwd_h | 基线 bwd_dh | 候选 bwd_dh |
|---|---|---|---|---|
| 32x32 | 顺序回退（`chunk_fwd_kernel_h` x1） | 并行（local x1 + scan x1） | 顺序回退（`chunk_bwd_kernel_dh` x1） | 并行（local x1 + fp32 scan group x1） |
| 64x64 | 并行（local x1 + scan x1） | 并行（同左） | 并行（local x1 + fp32 scan group x1） | 并行（同左） |
| 64x128 | 顺序回退 | 并行 | 顺序回退 | 并行 |
| 128x64 | 顺序回退 | 并行 | 顺序回退 | 并行 |
| 128x128 | 顺序回退 | 并行 | 顺序回退 | 并行 |

谓词特异性检查（T128，候选树）：白名单外的 `32x64`、`64x32`、`256x64` 仍然是
`parallel_fwd_h=False / parallel_bwd_dh=False`，回退 kernel 各命中 1 次，
说明改动没有意外放宽到其它形状（`agent-results/raw/specificity.jsonl`）。

## 正确性（与精确基线提交同种子同输入，两进程）

流程：基线进程保存 `o/ht/dq/dk/dv/dg/dh0` 及状态 `h/ht_state/dh/dh0_state`，
候选进程用同 seed 重算并逐张量比较（脚本
`agent-results/scripts/gla004_case.py` 的 `--save/--compare`）。
B1，H4，FP16，`gate_logit_normalizer=1.0`，`T=256`：

| 形状 | 最大 rel_rms（任何张量） | 最大 max_abs | NaN/Inf | ALL_PASS |
|---|---:|---:|---|---|
| 32x32 | 1.31e-06（dk） | 1.2e-4 | 无 | True |
| 64x64 | 0（逐位一致） | 0 | 无 | True |
| 64x128 | 6.33e-06（h） | 9.8e-4 | 无 | True |
| 128x64 | 2.93e-06（h） | 4.9e-4 | 无 | True |
| 128x128 | 2.08e-06（h） | 4.9e-4 | 无 | True |

四个候选形状的 `o`（输出）与基线的 max_abs 均为 0；`dv`、`dq`、`dk`、`dg`、
`dh0` 的差异都在 fp16 舍入量级。`ht_state`、`dh`、`dh0_state` 的 rel_rms 均
<= 1.4e-7。逐张量全表见 `agent-results/raw/correct_T256.jsonl`。

T64（B1,H4）五个形状同样全部 `ALL_PASS`；该 T 下每个形状只有 1 个 chunk，两条
路径几乎逐位一致，最大 rel_rms 1.33e-7、max_abs 1.19e-7
（`agent-results/raw/extra_T64.jsonl`）。T512 抽查 32x32 与 128x128 也全部通过
（`agent-results/raw/extra_T512.jsonl`；32x32 最大 rel_rms 4.2e-6，128x128 3.9e-6）。

### 独立递推参考交叉检查

`agent-results/scripts/gla004_recurrence.py` 用 fp64 逐步递推
`h <- h*exp(g); h <- h + k v^T; o <- q h` 并 autograd 求梯度，与候选路径比对
（B1,T96,H2,gln=1.0）。五个形状 `ALL_PASS`，rel_rms 均在 7e-5–3e-4（fp16 输出
本身的舍入量级），无 NaN/Inf。这验证的是"候选与数学定义一致"，不是基线等价性；
基线等价性由上面的逐张量对比给出。

## 性能口径与原始数据

计时口径：`torch.gcu.synchronize()` 包住每次调用，warmup 3 次后每进程每阶段
6 个样本取中位数；基线/候选**交替独立进程**，共 3 轮；报告"轮中位数的中位数"。
包含 launch + 执行 + Python 开销，**不是** device-event kernel 时间。冷编译
单列，绝不用于推算加速比。

脚本：`agent-results/scripts/drive_ab.py`（T256 三轮交替）、
`drive_extra.py`（T64/T512）、`gla004_case.py`（单 case 探针/正确性/计时）、
`summarize.py`（汇总）。原始 JSONL 在 `agent-results/raw/`。

### 冷编译（单列，不作加速依据）

每个新进程的首次 fwd+bwd 包含 Triton 编译，实测 2.7 s–51 s，且在同一形状上
基线/候选之间也不稳定（例如 T256 32x32：基线 51.0 s vs 候选 10.0 s；T512 32x32：
基线 2.8 s vs 候选 10.1 s）。这与"候选新增 4 个形状的 specialization"一致，
但没有足够样本区分编译缓存状态与主机负载，**不下结论**。

## 不确定性与限制

- 主机为共享环境，端到端 10 ms 量级波动可达 2x；阶段级（<7 ms）数据三轮稳定，
  端到端数据不稳定。所有倍数只对阶段级成立。
- 主矩阵只覆盖 B1,T256,H4；T64/T512 与 B/H 扩展仅做少量抽查，未覆盖 B>1、H 变化、
  变长（cu_seqlens 非 None 时本来就不走并行路径）、`state_v_first=True`、
  BF16、其它 chunk_size、`split_size` 变化。
- 门控只测了 1.0（主矩阵）、0.1 与 10.0（抽查）。已知两条路径在极端门控都可能
  NaN，本次未触发，但这不构成安全性证明。
- 正确性判据 `max_abs <= 1e-6 or rel_rms < 4e-3` 与仓库测试同量级；它证明
  fp16 舍入级一致，不证明逐位一致（64x64 控制组逐位一致是特例）。
- 白名单是实验性硬编码；没有做 tile 选择、num_warps/num_stages 的 shape-specific
  调优，也没有评估显存占用（`local_state` 为 `B*NT*H*K*V` fp32）。
- 冷编译时间在形状间差异大，未做 compile-cache 隔离实验。
