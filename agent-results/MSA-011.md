# MSA-011 · C200 长 prefill direct 逐页物理地址预解析

- **日期**：2026-11-25
- **基线提交**：`fb664f8c0ac0fbac1aa7dbcfbc282fb8cba50424`
- **实验分支/位置**：独立 clone `.cache/agent-workspaces/msa-physical-pages-fb664f8`，分支 `agent/enflame-msa-physical-pages`（未 push、未 merge，默认生产路由未改动）
- **设备**：GCU 5（PCI `0000:83:00.0`，ZIXIAOC200，Uuid `TS9B37120204`），CPU 160–191，全程 `taskset -c 160-191`，单卡独占（`efsmi pmon` 无其它进程）
- **结论**：**等价性通过，端到端有小幅但稳定的正收益**。`_gqa_sparse_fwd_direct` 自身 −0.084 ms，代价是 `_gqa_sparse_common_prefix` +0.054 ms，链路净 −0.029…−0.054 ms（0.6%–1.1%，三次独立进程 × 7 轮 A/B 中 candidate 在 20/21 轮更快）。收益主要来自把"每页一次 block_table 间接寻址"换成"每页一次连续 id 读"，远小于此前模拟的 0.522 ms。

## 1. 本轮唯一变量

packed-K 路径下，direct kernel 每处理一个 logical page 都要做：

```
blk  = tl.load(t_ptr_j)         # topk_idx[slot]
page = tl.load(bt_row + blk)    # 逐页间接寻址 block_table
```
即 13 个 page × 1024 program 的**依赖式**间接 load（第二次 load 的地址依赖第一次 load 的结果，且落在页循环体内，无法与 K/V DMA 重叠）。

候选改动：在**已经存在**的 shared-prefix launch（`_gqa_sparse_common_prefix`，64 programs，本来就要读 `ids`）里，顺带把本 group 的 16 个 TopK slot 一次性解析成物理页号写入 `phys_page`；direct kernel 改成按同样 slot 顺序直接读该 buffer。

关键约束（全部满足）：
- `phys_page[i]` 与 `topk_idx[i]` **同 shape/同 stride/同 slot 顺序**；
- 页循环里 `blk` 仍然来自 `topk_idx`，`c = blk * BLOCK_SIZE_K`、`pos_mask`、`boundary_check` 全部继续用 **logical** id；
- 原始随机物理页表原样使用（未改成 identity / 未 no-op）：`0/16384` 个 slot 的 logical == physical；
- 复用既有 shared prefix（64 group 全部 `counts == 3`）与既有 13 页页序，未改动；
- 仅新增 1 个 `torch.empty_like(topk_idx)` = 64 KiB int32 buffer（计入端到端）；
- 通用 API、`minimax_m3_sparse_attn` 默认路由、grouped8 短序列 bypass 均未改；开关是 `FLAG_ATTN_MSA_PHYS_PAGE=1` 叠在 `FLAG_ATTN_MSA_PACKED_K=1` 之上。

## 4. IR / lowering

`_gqa_sparse_fwd_direct`（packed，baseline → candidate）：

| 计数 | baseline | candidate |
|---|---|---|
| `memref.dma_start` | 9 | 9 |
| `memref.dma_wait` | 23 | 23 |
| `gcu.matmul` | 4 | 4 |
| `memref_ext.transpose_start` | 0 | 0 |
| `scf.for` | 3 | 3 |
| `memref.load` | 8 | 8 |
| shared / warps / stages | 0 / 1 / 1 | 0 / 1 / 1 |
| convgen | `tops_convgen_m8_n128_k128_bf16_fp32` + `…_bias_bf16_fp32` | 同 |

把 SSA 名归一化后逐行比对，**K/V 搬运与计算相关行完全一致**（271 行 `dma_*`/`gcu.matmul`/`memref_ext.*`/`mfence`/`vector.*` 完全相同，4 条 `gcu.matmul` 的 operand 形状与 `inputPrecision` 逐字相同，`transpose` 数量 0）：**QK / PV / softmax 的 lowering 没有变化**。

direct kernel 的差异只有页循环里的"页号来源"：
- baseline：`memref.dma_start/dma_wait` + `memref.load` 取 `blk`，然后 `muli blk,512 → addi (bt_row) → ptr2int/int2ptr` 间接取页；
- candidate：仍是 `dma_start/dma_wait` + `memref.load`（取 `blk`，供 causal 用），另有一对 `dma_start/dma_wait` + `memref.load` 取预先解析好的页号，少了 `blk` 参与页地址的 `muli/extsi` 间接链；
- 两版页循环外层 `gcu.border` 数（78）、`vector.store`（63）、`memref.dealloc`（28）、`gcu.matmul`（2）等结构计数相同。

`_gqa_sparse_common_prefix`：`dma_start 10→10`、`dma_wait 38→45`、`scf.for 9→11`、`memref.load 7→13`——这就是新增 gather 的全部代价所在（多了 7 次 wait、2 个循环、6 次 load），shared 仍 163840，convgen 未变。

## 5. 端到端与分阶段（三次独立进程 × 7 轮交错 A/B）

固定 7 轮，每轮内按 `baseline/candidate` 交替顺序、逐阶段配对采样；三次运行分别是三个新进程（含冷编译与 warmup 各 3 次，不计入样本）。

| 进程 | 阶段 | baseline 中位数 | candidate 中位数 | Δ | 加速比 | candidate 更快的轮数 |
|---|---|---|---|---|---|---|
| 1 | chain（Score→TopK→Attention） | 5.0708 ms | 5.0372 ms | **−0.0336 ms** | 1.0067× | 7/7 |
| 1 | attn（整个 attention 算子） | 3.6720 ms | 3.6361 ms | −0.0359 ms | 1.0099× | 7/7 |
| 1 | score_topk | 1.5467 ms | 1.5433 ms | −0.0034 ms | 1.0022× | 4/7 |
| 2 | chain | 5.0844 ms | 5.0305 ms | **−0.0539 ms** | 1.0107× | 7/7 |
| 2 | attn | 3.6801 ms | 3.6468 ms | −0.0333 ms | 1.0091× | 7/7 |
| 2 | score_topk | 1.5487 ms | 1.5415 ms | −0.0072 ms | 1.0047× | 4/7 |
| 3 | chain | 5.0604 ms | 5.0313 ms | **−0.0292 ms** | 1.0058× | 6/7 |
| 3 | attn | 3.6728 ms | 3.6266 ms | −0.0462 ms | 1.0127× | 7/7 |
| 3 | score_topk | 1.5475 ms | 1.5424 ms | −0.0051 ms | 1.0033× | 4/7 |

`score_topk` 两个 arm 走的是同一份代码，差值是噪声（±0.01 ms，符号会翻），可当作本轮噪声尺度：**chain 的 −0.03…−0.05 ms 刚刚高于该噪声底**。

### 分 kernel 归因（同一次 benchmark 内单独测量，12 次/arm）

| kernel | baseline | candidate | Δ |
|---|---|---|---|
| `_gqa_sparse_common_prefix` | 0.318 ms | 0.372 ms | **+0.054 ms** |
| `_gqa_sparse_fwd_direct` | 3.189 ms | 3.104 ms | **−0.084 ms** |

即：**收益 0.084 ms，代价 0.054 ms，净 ≈ 0.03 ms**。这与 A/B 的链路差一致，说明链路收益不是测量假象，但它确实很小。

## 6. 已试过并放弃的路线（保留失败结论）

| 方案 | 做法 | 结果 |
|---|---|---|
| A · 独立 gather kernel | `_msa_resolve_phys_pages`，ROWS=16 分批 gather，单独 launch | 等价通过；direct 3.103 ms（−0.085 ms），但 resolver 自身 0.074 ms，净 ≈ −0.01…−0.04 ms，与噪声同级；ROWS 扫描 1→0.757、4→0.609、8→0.109、16→0.095、32→0.103、64→0.099、128→0.144 ms |
| B · kernel 内批量预取 | 页循环前一次性向量载入 16 个 logical id，循环内用 `tl.sum(tl.where(...))` 选页 | bitwise 相同，但 direct 3.191 ms vs 3.187 ms，**无收益**（选择逻辑进了页循环关键路径） |
| C · 折进已有 prefix launch（**本轮采纳**） | 在 `_gqa_sparse_common_prefix` 里顺带解析并写出 | 见上，净 ≈ −0.03 ms |

A 的教训：单独 launch 的 0.074 ms 几乎正好吃掉 direct 省下的 0.086 ms，所以"预解析"必须先找到**不新增 launch** 的落点才有意义；折进 prefix 后又把 0.054 ms 加到了 prefix 的关键路径上，因此最终净收益只有一个噪声量级之上的小值。

## 7. 复现

脚本：`agent-results/msa011_physical_pages.py`（在 clone 根目录执行；只往 `agent-results/raw/` 写日志，不污染 Git worktree）

```bash

taskset -c 160-191 /flagos/bin/python agent-results/msa011_physical_pages.py --device 5 --benchmark --rounds 7
```

脚本内置硬门禁：`--device` 必须是 5、PCI 必须是 `0000:83:00.0`、`efsmi pmon` 不得有本进程树之外的 pid、usage 必须 ≤1%，任一不满足直接退出且不报任何数字（退出码 3/4）。benchmark 在报数字之前先做一次 bitwise 等价门禁，不等价则拒绝输出耗时。

原始证据：`agent-results/raw/{verify.log, bench_1.log, bench_2.log, bench_3.log, ir/}`（`ir/` 含 prefix/direct × base/cand 的 ttir/ttgir/gcuir/llir 与 metadata）。

**轮数下限（实测教训）**：提交后又跑了一次 `--rounds 3`，得到 chain `5.3113 → 5.0289`（−0.2824 ms），看似收益放大 8 倍，实际上第 0 轮 baseline 是冷启动的 5.2597 ms、第 2 轮 candidate 有一个 5.4285 ms 的离群点——3 轮的中位数被这两点直接带偏。脚本因此把 `--rounds` 默认值改为 7，并在此值以下打印告警。**本节报告的 −0.03…−0.05 ms 只来自三次 7 轮运行**，请勿用短程运行复核。

## 8. 结论与建议

- 逐页物理地址预解析**可以做到 bitwise 等价**，且页表保持随机、因果掩码仍由 logical id 决定。
- 端到端**有正收益但很小**：链路 5.07 ms → 5.03 ms（约 −0.03…−0.05 ms，0.6%–1.1%），三次独立运行方向一致。相对 QK 控制实验里模拟的 0.522 ms，本次真实收益低一个数量级——因为模拟去掉的是"逐页 K 搬运 + 页地址查询"两者，而本实验只去掉了后者中的间接寻址部分。
- 成本结构清楚：direct −0.084 ms / prefix +0.054 ms。若要进一步放大收益，方向不是继续优化 gather，而是让解析结果**顺带消掉 prefix 里已有的那次 `ids` 读取**，或把 13 页的 K 搬运本身与 id 解析重叠——这两条都超出"只做页号预解析"的范围。
- 建议：作为 opt-in 实验保留（默认路由零影响、可一键回退），**暂不建议转正**——0.03 ms 量级不足以支撑多一个 64 KiB buffer 和一条 env 分支的维护成本。等你明天定夺。
