## Call path under test

Prefill (benchmark shape `[B,Q,S,KVH,H]`):
1. `minimax_m3_index_score` -> `_index_block_score_kernel`
2. `minimax_m3_index_topk` -> one of radix/streaming/partial top-k paths
   (must record which path is selected; fallback is not accepted as the target kernel)
3. `minimax_m3_sparse_attn` -> `_gqa_sparse_fwd*` selected by `_prefill_qh8_kernel_choice`

Decode:
1. `minimax_m3_index_decode` -> `_decode_index_score_kernel` + partial/merge top-k
   (or `_decode_topk_identity_kernel` on the identity path)
2. `minimax_m3_sparse_attn_decode` -> `_gqa_sparse_decode*` / KV-outer path

The benchmark per-step numbers are separate `bench_fn` medians (device events).
They are **stage-only** and must not be summed and called an end-to-end latency.
This task measures a separate synchronized whole-call number.

If a reference cannot be produced, the case is marked **untested**, not passed.

## Timing definitions (used in phase 2)

- **stage-only**: device-event elapsed time around exactly one stage call, after
  compilation/warmup; values are medians of raw per-iteration samples. Includes any
  allocations and any auxiliary kernels that stage launches.
- **whole-call**: device-event elapsed time around the full composed call
  (prefill score+topk+attention, or decode index+attention), synchronized at both ends.
  It is not the sum of stage-only medians.
- Compilation (first call) is reported separately and excluded from steady state.
- Peak memory: `torch.gcu.max_memory_allocated` / reset per case.
- Launch count: `torch.profiler` CPU/runtime events are used only for launch counting
  and host-side attribution. This image's smoke test showed no attributable device
  kernel durations; missing device events are not interpreted as zero kernel time.
- Every representative shape gets at least 3 rounds; raw samples and medians are kept
  under `agent-results/logs/`.

## Separation of failure classes

- Model-gateway failure: no model calls are used by this task; if an external model
  gateway is unavailable, that is recorded as gateway failure, not GCU failure.
- GCU failure: efsmi error, device allocation failure, kernel launch failure, or
  reproducible device-side numerical error.
- Compilation failure: Triton/FlagTree compiler error, recorded separately with log.
